# 内容安全与审核（Content Safety）

> 🌐 语言：**中文** ｜ [English](README.en.md)

> 应对视频生成审核拦截、保障稳定产出的横切主题，适用于所有输入路径。
> 返回[方法总览](../README.md)

---

## 一、主题定位

视频生成有内容安全审核。当 prompt 或参考素材命中敏感内容时，任务会被拦截（`ContentRiskBlocked` / `*SensitiveContentDetected` 等）。**`--force` 绕不过内容审核**--它只跳过参数校验，不跳安全策略。本主题讲如何从源头规避、被拦截后如何调整。

### 适用场景

- 生成被审核拦截，需要排查原因
- 设计 prompt 时主动规避敏感词
- 参考素材合规检查
- 需要稳定批量产出，降低拦截率

---

## 二、审核拦截表现

### 常见错误码 / 状态

| 错误 | 含义 |
|------|------|
| `ContentRiskBlocked` | 内容风险拦截 |
| `*SensitiveContentDetected` | 检测到敏感内容 |
| 命中敏感词 / 版权 | prompt 或素材含敏感/版权内容 |

### 关键认知

- **`--force` 无效**：`--force` 只跳过**参数校验**（让不支持的参数透传），**不跳内容安全策略**
- 拦截发生在服务端，客户端无法绕过
- 被拦的任务不会产出视频，但可能已计入部分成本（以实际计费为准）

---

## 三、敏感内容主要类别

| 类别 | 典型 | 规避 |
|------|------|------|
| 暴力/血腥 | 打斗、伤口、武器特写 | 弱化描述，用象征/隐喻 |
| 色情/暴露 | 过度暴露、性暗示 | 调整着装、构图 |
| 政治敏感 | 政治人物、政治符号、旗帜 | 避免具体政治元素 |
| 真实人物 | 明星、公众人物 likeness | 用虚构角色描述 |
| 版权内容 | 知名 IP 角色、品牌 logo | 用通用描述替代 |
| 违法行为 | 毒品、犯罪过程 | 删除相关描述 |
| 恐怖/极端 | 恐怖主义、极端场景 | 避免相关元素 |
| 安全体验限额 | 触发 SetLimitExceeded，模型服务暂停 | 控制台模型管理关闭「安全体验模式」或调高限额 |

---

## 四、Prompt 规避策略

### 原则：正面描述，避免否定

模型对**否定描述弱**（"不要出现血"可能反而强化血的概念）。用正面替代描述：

| 差（否定/敏感） | 好（正面替代） |
|----------------|----------------|
| "不要有血腥" | "动作利落，特写表情坚毅" |
| "不是真人明星" | "一位虚构的年轻女性角色" |
| "没有武器" | "双手自然垂下" |

### 具体化而非具名

- 避免具名真实人物/IP -> 用外貌特征描述虚构角色
- 避免品牌 logo -> 用"一款智能手机"而非具体品牌
- 避免具体政治符号 -> 用通用场景元素

### 弱化敏感强度

- 暴力 -> 象征性动作（"对峙""凝视"而非"打斗流血"）
- 危险 -> 隐喻（"风雨欲来"而非具体灾难）
- 用风格化稀释（动画/水彩风格比写实更易过审）

---

## 五、参考素材合规

I2V / R2V / 音频驱动的**输入素材**也会被审核：

| 素材类型 | 检查点 |
|----------|--------|
| 首帧图 | 图像内容是否含敏感元素 |
| 参考视频 | 视频画面是否合规 |
| 参考音频 | 音频内容/歌词是否敏感 |

### 素材自检

- 图片：是否含真人面孔、品牌 logo、暴力/暴露元素
- 视频：画面是否合规、是否有版权内容
- 音频：歌词/语音是否敏感

> 素材违规时，换 prompt 没用，必须**换素材**。

## 六、被拦截后的处理流程

```
任务被拦 (ContentRiskBlocked)
   │
   ▼ 1. 定位来源
   │   ├─ prompt 敏感?    -> 改 prompt（正面替代/弱化）
   │   ├─ 输入素材敏感?   -> 换素材
   │   └─ 不确定?         -> 逐项排除（先去掉素材只 T2V 试）
   │
   ▼ 2. 调整后重试
   │   改一处试一次，定位具体敏感点
   │
   ▼ 3. 仍被拦?
       ├─ 进一步弱化描述
       ├─ 换风格（写实->动画/水彩）
       └─ 用 doctor 诊断
```

### 用 doctor 诊断拦截

要结构化的拦截原因 + 修复指引，用 `arkcli doctor error <code>`：

```bash
arkcli doctor error ContentRiskBlocked
```

生视频拦截的 5 个 subtype doctor 全覆盖，会给出具体 subtype 与修复建议。详见 arkcli-doctor skill。

## 七、批量产出的稳定性策略

批量生成时，高拦截率会浪费成本。预防措施：

| 策略 | 说明 |
|------|------|
| prompt 模板预审 | 批量前先单条试，确认 prompt 过审再批量 |
| 素材统一合规 | 批量前所有素材过一遍自检 |
| 风格统一用安全风格 | 写实风险 > 动画/水彩，批量优先安全风格 |
| 隔离失败任务 | 单条失败不影响整批，记录失败项单独重试 |
| 用 draft 先试 | `--draft` 便宜，先批量试过审率，再正式跑 |

---

## 八、命令模板

```bash
# 1) 被拦后诊断
arkcli doctor error ContentRiskBlocked

# 2) 逐项排除定位（去掉素材只 T2V 试，看是否 prompt 问题）
arkcli +gen --model "$MODEL" "<只保留 prompt，去掉 --input>" --open

# 3) 用安全风格弱化
arkcli +gen --model "$MODEL" \
  "水彩画风格，一位虚构旅人在山间行走，宁静氛围" --open

# 4) 批量前先 draft 试过审率
arkcli +gen --model "$FAST" --draft --resolution 480p \
  "<批量 prompt 模板>" --open
```

## 九、踩坑点

| 现象 | 原因 | 处理 |
|------|------|------|
| `--force` 仍被拦 | force 不跳内容审核 | 从 prompt/素材源头调整 |
| 改了 prompt 还被拦 | 是素材违规 | 换素材，不是改 prompt |
| 否定描述无效 | 模型对否定弱 | 用正面替代描述 |
| 批量大量被拦 | prompt/素材未预审 | 批量前单条试 + draft 试过审率 |
| 真人 likeness 被拦 | 具名真实人物 | 用虚构角色外貌描述 |
| 不知哪违规 | 多来源难定位 | 逐项排除（去素材只 T2V 试） |

---

## 十、检查清单

- [ ] prompt 用正面描述，避免否定句
- [ ] 不具名真实人物/IP/品牌，用特征描述
- [ ] 输入素材已自检（图/视频/音频）
- [ ] 敏感元素已弱化或风格化
- [ ] 批量前先单条 + draft 试过审率
- [ ] 被拦后用 `arkcli doctor error` 诊断
- [ ] 逐项排除定位违规来源（prompt vs 素材）
- [ ] 不依赖 `--force` 绕审核
