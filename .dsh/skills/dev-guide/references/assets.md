# 资产与文件规范

> 返回 [SKILL.md](../SKILL.md)

## 1. 格式分工

| 类型 | 格式 | 理由 |
|------|------|------|
| 成品、对照 | **PNG**（无损、去元数据 `tEXt`） | JPEG 会引入约 1.21 的平均通道差，吃掉"无操作 < 1.5"的判据 |
| 合并图、审计图 | **JPEG** | 体积优先，不参与像素判据 |
| 缩略图 | JPEG，700 px box-downscale | 每张约 60–90 KB，网格图靠它秒开 |
| 视频成品 | `.mp4` | 当前单文件最大约 13 MB |
| 音频 | `.mp3` | 旁白/配乐 |

## 2. 体积与上限

- GitHub 单文件硬限 **100 MB**（>50 MB 告警）；当前最大文件约 13 MB。
- **不用 Git LFS**：所有文件都远低于限制，引入 LFS 只会增加协作成本。
- 仓库约 550 MB / 1059 个内容文件；GitHub Pages 站点上限 1 GB，尚有余量。

## 3. 不入库清单

| 目录/模式 | 说明 |
|-----------|------|
| `work/` | 逐轮探索产物（候选、失败件、中间件） |
| `out/r*/` | 逐轮产物目录（bone-china-doll） |
| `out/v3-*/`、逐镜头 `shot*.mp4`、`*_test*.mp4` | 视频中间件与测试件 |
| `__pycache__/`、`*.pyc` | Python 缓存 |
| `.verify/`、`.scratch/` | 技能校验输出与本地临时目录 |

这些目录由各处的 `.gitignore` 保证不入库；**文档里指向它们的链接属于"预期断链"**（`i18n.py check` 单独计数）。

## 4. 可复现性说法

中间产物不入库时，理由必须写清是**确定性可复现**，不能只说"太大"：

- 图像类：固定 seed + 固定 prompt → 可逐像素复现（本项目的 Z-Image-Turbo 已验证字节级一致）。
- 视频类：云端 API 产物不可逐像素复现，旧版本属**已废弃版本**，定稿都在仓库里 —— 要如实写明。

## 5. 命名

- 期目录：`period-NN/`（补零两位）。
- 成品：`NN-<镜头名>.png`（NN 为该期内序号）。
- 对照：`controls/<底座物种>.png`。
- 合并图：`sheet.jpg`（另有子主题级 `sheet-thumb.jpg`）。
- 轮次记录：`rNN.md` / `<缩写>-rN.md`、`rNN-review.md` / `<缩写>-rN-review.md`、`rNN-audit.jpg`（命名不完全统一，解析时用宽容正则）。
