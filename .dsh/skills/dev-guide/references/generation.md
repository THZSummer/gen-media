# 生成纪律（图像 / 视频项目）

> 返回 [SKILL.md](../SKILL.md)

## 1. 六条纪律

| 纪律 | 原因 |
|------|------|
| **期内恒定**：同一期内生境 / 光线 / 机位 / 画布一致；期间可各异 | 期内变量一多，评不出"是哪一处改动起作用" |
| **每轮一个同轮底座对照** | 跨轮对照会被其他变量污染（规律 76） |
| **姿态句不点名目标部位** | 点名会把整只供体渲染出来（规律 79） |
| 定稿只收 `score.py` 判 ✅ 的图，由 `curate.py` 提升进期目录 | 保证期目录里没有残次品 |
| 每轮留 `*-review.md`（A–E 评分 + 逐条优缺点）与 `*-audit.jpg`（审计图） | 可追溯、可复核 |
| 客观指标只当**单向警报** | 区域差 < 1.5 说明移植句是空操作；但"有差异"不证明移植成立 |

## 2. 评分维度与门槛

| 维度 | 权重 |
|------|------|
| A 移植到位 | .30 |
| B 底座完整 | .20 |
| C 解剖可信 | .20 |
| D 摄影统一 | .15 |
| E 概念可读 | .15 |

**门槛**：`fatal` 非空 / A<3 / B<3 → 不合格；总分 ≥4.0 且 A≥4 → 首选定稿；≥3.5 → 成品；其余为备选（**不纳入成品**）。

## 3. 像素判据

- 判断"改动是否生效"看**解码后的像素**，不看文件哈希：ComfyUI 把执行图写进 PNG 的 `tEXt`，同像素也会哈希不同。
- 工具：`image-gen/skills/image-tools/scripts/pngdiff.py`（附 PSNR / SSIM）。
- **成品与对照必须 PNG**：JPEG 会引入约 1.21 的平均通道差，吃掉"无操作 < 1.5"的判据。
- 合并图 / 审计图用 JPEG（控体积）；子主题缩略图 700 px box-downscale（约 60–90 KB）。

## 4. 一个标准轮次

```sh
cd image-gen/projects/<项目>
python3 run_round.py <轮次> --dry     # 先看逐字 prompt，不出图
python3 run_round.py <轮次>           # 出图（Z-Image-Turbo 约 25 秒/张）
python3 score.py ...                  # 评分复核，判 ✅
python3 curate.py ...                 # 把 ✅ 的成品提升进 period-NN/
bash make_sheet.sh period <子主题> <期>   # 重出该期合并图
```

轮次记录要写清：本轮验证了什么、哪些不合格及原因、结论是**机制发现**（编号续写）还是**否定结论**。
否定结论与成品同样有价值，必须写进项目总结，不要只留成功案例。

## 5. 不确定就标注

估算、推测、未验证的结论要在文档里显式标注（例如"假设，未验证"、"样本仅 1 期"）。
宁可交一张不完美的成品加一句诚实的不足，也不要凑数或夸大。
