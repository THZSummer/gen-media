# 内容安全（Content Safety）

**用途**：让生成稳定通过平台审核，把审核当作**设计约束**前置处理。

> Ark 会对 prompt 和参考素材做内容审核；命中策略即拦截——**`--force` 之类的参数绕不过审核**。

## 何时用

- 生成被拒、提示内容违规
- 题材可能敏感（人物、冲突、商标）
- 用真人照片或含 IP 元素的图作为 `--input`

## 常见拦截来源

| 类别 | 典型触发 | 处理方向 |
|------|----------|----------|
| **人物/肖像** | 真实名人、可识别真人 | 改为"虚构角色"，不点名、不描述真实身份 |
| **成人/擦边** | 暴露、性暗示、暧昧姿态 | 明确服装与姿态，走正常着装表达 |
| **暴力/血腥** | 伤害、武器指向、伤口细节 | 弱化冲突表达，去具体伤害描写 |
| **未成年人** | 涉及未成年人的敏感场景 | 避免风险组合，改成年角色 |
| **版权/IP** | 明确 IP 角色名、商标 | 用原创描述替代，勿直呼 IP 名 |
| **违禁/敏感符号** | 政治敏感、违禁品、危险行为教学 | 直接回避该题材 |
| **文字内容** | 图中文字夹带违规信息 | 不要求生成违规文字 |

> 参考素材（`--input`）同样被审核：底图违规，编辑任务也会被拒。

## 规避策略

1. **不点名真人/IP**：用外观特征描述替代专有名词
2. **姿态与着装写清楚**：明确"正常站姿、日常服装"
3. **正向表述**：描述"想要的"而非"不要的"
4. **参考素材先体检**：用作 `--input` 的图先自查
5. **拆解敏感组合**：某些元素单独无害、组合触发，调整场景或角色设定
6. **保留失败样本记录**：把被拒 prompt 记入项目 README，避免团队重复踩坑

## 被拒后的处理流程

```
被拒 ──► 定位触发点（人物？姿态？素材？）──► 最小改动重写 prompt ──► 重试
   │
   └─► 连续被拒：换表达方式 / 换题材角度 / 查平台策略，不要原样硬刷
```

- **不要**原样重试：同样 prompt 大概率同样被拒
- **不要**靠加参数绕过：审核在内容层
- **不要**为过审牺牲核心意图：必要时换方案

## 踩坑点

- ⚠️ **先被拒才发现**：安全检查放在规划阶段，而非生成阶段
- ⚠️ **间接指涉照样被拒**：昵称、绰号、谐音同样可能命中
- ⚠️ **参考图是盲区**：只检查 prompt、忘了 `--input` 也被审
- ⚠️ **局部合规 ≠ 整体合规**：改一处仍可能触发别的策略，复审整段 prompt
- ⚠️ **过审不等于可用**：商用还需自行确认版权与肖像权

## 检查清单

- [ ] prompt 不含真实人物名 / IP 名 / 商标
- [ ] 角色年龄与场景无风险组合
- [ ] 服装与姿态描述明确、正常
- [ ] 所有 `--input` 参考素材已自查
- [ ] 被拒记录已写入项目 README
- [ ] 商用前已确认版权 / 肖像权归属
