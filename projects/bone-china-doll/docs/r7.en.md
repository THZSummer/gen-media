## Why change the engine

R1–R6 with Z-Image-Turbo (8–16 steps) had already solved **composition, camera, adult proportions and composition hygiene**, but the user judged that "the detail is still not rich enough, not real enough". R6's bottleneck was not the prompt wording but **the engine's rendering ceiling**: a distilled Turbo model at 8–16 steps, a single model, with a limited detail hierarchy (lace looks moulded, embroidery has no thread direction, gems have no settings).

The server's model list had stronger options:

| Candidate | File | Judgement |
|------|------|------|
| **Qwen-Image 2512** | `qwen_image_2512_fp8_e4m3fn.safetensors` + `qwen_2.5_vl_7b_fp8_scaled.safetensors`(type=`qwen_image`) + `qwen_image_vae.safetensors` | ✅ Adopted: a 20B-class MMDiT, markedly stronger on detail/realism, and **supports a true negative prompt** |
| boogu-image-turbo | `boogu_image_turbo_fp8_scaled.safetensors` | Alternative, untested |
| z-image-turbo | currently in use | Kept as a fast draft engine |

> A probe found the server has a `TextEncodeQwenImage21` node (native prompt+negative_prompt), but the classic `CLIPTextEncode` + `qwen_image` clip type was already verified working, so the classic graph was adopted.

## New capability (now baked into the skill)

`.agents/skills/text-to-image-comfyui/scripts/comfyui_qwen.py` — a second engine, sharing queueing/polling/downloading with `comfyui_gen.py`:

```bash
python3 comfyui_qwen.py --check                     # 校验三个模型文件在位
python3 comfyui_qwen.py --prompt "..." --negative "..." \
  --width 1024 --height 1360 --steps 24 --cfg 3.0 --seed 7 --out-dir out/
```

Graph structure: `UNETLoader → ModelSamplingAuraFlow(shift 3.0) → KSampler(euler/simple, cfg)`;
`CLIPLoader(qwen_image) → CLIPTextEncode 正/负`; `EmptySD3LatentImage → KSampler → VAEDecode → SaveImage`.

Project side: `run_round.py` was upgraded to **dual engine**, and the round config gained an `engine` field (`zimage` / `qwen`).

### Negative prompt (NEG_Q)

```
cracks, crazing, crackle pattern, broken, damaged, chipped, dirty, dust, stains, plastic, vinyl,
waxy skin, cartoon, anime, chibi, toy-like proportions, oversized eyes, blurry, low detail,
low resolution, oversaturated, harsh flash, cgi, 3d render, extra limbs, extra fingers, deformed
hands, floating objects, text, watermark, signature, logo, busy background
```

> Before R6, `craquelure` (crazing) was written into the positive as "detail", and Qwen amplified it into **cracks all over the face** (see `.scratch/qwen-probe.png`). From R7 all cracking was moved into the negative and replaced with `pristine flawless glaze`.

## Self-check

| Dimension | Score | Change vs R6 |
|------|------|-----------|
| Detail richness | ★★★★★ | ↑↑ **Lace has warp and weft, embroidery has thread direction, pearls are rendered one by one, gems have settings**, the metal tiara has carving |
| Realism | ★★★★★ | ↑↑ Flawless glaze + translucency at thin areas + **ball-joint neck/wrist seams**, reaching the look of "a photograph of a real physical artifact" |
| Princess | ★★★★★ | ↑ Adult princess temperament + heavy tiara + gown layering |
| No distortion | ★★★★☆ | ↑ Finger structure normal, no extra limbs; image 1's face is slightly "flawless to the point of being unreal" |
| Image | ★★★★★ | ↑ Clean background, light ratio with hierarchy |

**Conclusion: R7 is the single biggest leap in the whole project; switching engines was worth far more than continuing to tune the prompt.** From R7, 3 images per round.

**Still improvable**:
1. The face tends toward "flawless to the point of feeling plastic" (porcelain should be like this, but it needs a little micro relief in the glaze)
2. The light is rather flat and lacks sculptural quality — next round use **chiaroscuro / Rembrandt**
3. The costume can be more sumptuous (brocade, gold thread, gemstone prongs)
4. Resolution can go up one more notch (1024×1360 → 1152×1536) in exchange for detail
