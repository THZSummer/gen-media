# Round 14 (R14) · Resolution ablation — negative result: raising resolution **does not raise detail density**

> 🌐 Language: **English** | [中文](r14.md)

> Back to [project index](../README.en.md) ｜ Previous round [R13](r13.en.md)
> Purpose of this round: R13 has confirmed that the baseline is solid and that macro is unattainable, so we test the last intuitive hypothesis —
> **is "not enough detail" caused by insufficient resolution?** The answer is **no**.

## Experimental design (strictly single-variable)

**The prompt is character-for-character identical** (`BASE_Q10` + the window-light suffix from the R10 final), **all seeds = 1400**, steps/cfg unchanged,
**only the resolution changes**, with three values (all side lengths multiples of 16, aspect-ratio deviation from 1280×1712 < 0.3%):

| # | Name | Size | Pixels | Linear scale | Time |
|---|------|------|------|----------|------|
| — | Baseline (R13 control) | 1280×1712 | 2.19 MP | 1.00× | ≈13 min |
| 1 | res-125 | 1600×2144 | 3.43 MP | 1.25× | ≈50 min |
| 2 | res-140 | 1792×2400 | 4.30 MP | 1.40× | ≈60 min |
| 3 | res-150 | 1920×2560 | 4.92 MP | 1.50× | ≈70 min |

> ✅ **Side conclusion: an RTX 4060 Ti 8GB can run Qwen-Image 2512 at 4.92 MP without OOM** (it merely takes about 5× as long).

## Key metric: **information per pixel (bytes/px)**

The PNG file size can serve as a rough proxy for image information (higher entropy and denser texture compress to a larger file). After normalising with `bytes / number of pixels`:

| Size | MP | File | **bytes/px** | Relative to baseline |
|------|----|------|-------------|----------|
| 1280×1712 | 2.19 | 2.77 MB | **1.2633** | — |
| 1600×2144 | 3.43 | 4.58 MB | **1.3345** | +5.6% |
| 1792×2400 | 4.30 | 5.69 MB | **1.3223** | +4.7% |
| 1920×2560 | 4.92 | 6.09 MB | **1.2380** | **−2.0%** |

> **Reading**: pixels grew 2.25×, while **detail density per unit area stayed essentially flat** (at most +5.6% at 3.43 MP,
> and at 4.92 MP it is actually **below** the baseline). In other words, raising resolution mainly buys **a larger canvas**,
> not **denser detail**.

## Visual reading (image by image)

| # | Result |
|---|------|
| 1 (3.43 MP) | Quality on a par with R10/R13; **changing resolution at the same seed makes Qwen re-plan the composition** → this one gives a more complete half-body + both arms + **ball-joint seams at both wrists**, and paradoxically the highest image information |
| 2 (4.30 MP) | Same quality; the composition is rearranged once again |
| 3 (4.92 MP) | Same quality (adult face, porcelain translucency, gold-thread brocade, sapphires and lace all up to standard), but **the lowest detail density of the three** and the longest runtime |

## Conclusions (three)

1. **Resolution is not a lever for "detail richness"**. Adding more pixels at the 1280×1712 level buys only a larger canvas;
   to genuinely raise detail density you must change the mechanism (more steps / higher cfg / two-stage refinement / a stronger model), not add resolution.
2. **The cost is extremely asymmetric**: 4.92 MP takes about **5×** as long as 2.19 MP, and the gain is 0 or even negative → **abandon this direction**.
3. **Changing resolution at the same seed rearranges the composition**: resolution is not a neutral knob; it is also a **composition knob**.
   This has a positive use for the project → see R15: **use the canvas aspect ratio to manipulate composition**.

## Changes for the next round (R15)

1. Return the resolution to **1280×1712** (the best cost-performance), with the baseline still `BASE_Q10`
2. **Shift the main thrust to composition diversity** (the real defect of R10/R13: all three are busts)
   - Try **using the canvas aspect ratio** to force different compositions: an ultra-portrait ratio (1:2) to force a full figure, a square (1:1) to force a seated pose
   - Add a camera position never shot before: **back view / three-quarter back view** (to see the bun, the back of the tiara, the back of the gown)
3. Get **true macro** by **cropping** the R14 3.43 MP final (no longer written into the prompt)
