> 以《山海经》**原文为纲**的白描图赞连载：每期一件异兽，兽用白描墨线，赞录原文、卷次与郭璞注。
> 面向**小红书竖版图文**（3:4），严格考据、可逐字复核。

---

## 一、项目背景

- **项目名**：`shanhai-jing`（山海经图赞）
- **目标**：把《山海经》里可考的异兽，用中国传统**白描 + 图赞**制式逐件画出来，配原文、卷次与注，做成可持续连载的小红书图文。
- **差异化**：这个题材在 AI 绘画里极度饱和，靠"画得好看"无法胜出。本项目的立足点是**可核验的考据**：
  - 每件异兽标注**卷次 + 原文 + 郭璞注**，原文逐字核对（底本见 [PLAN.md](PLAN.md) 第二节）
  - **可数特征必须数对**——九尾就是 9 条、三首六目就是 3 头 6 目；计数不符直接判不合格（`fatal`）
  - 榜题与印章**由工具叠真字**，绝不由模型生成（实测模型会画乱码印章）
- **用途**：小红书图文连载（图赞主图 + 原文卡 + 系列封面）

## 五、制版工艺（R5–R9 修正后）

```
① 出图      Z-Image-Turbo 纯文生图 —— **点名神话生物的写法**（不用控制图）
② 制版      typeset_zanzhi.py：榜题 + 原文 + 卷次 + 边框（✅ 5 项排版自检；印章待字库）
③ 核数      裁尾区放大目视点数并留档 —— 读作九尾即可，不作机械确证
④ 评分      A–F 六维（F 气韵 .25），`fatal` 仅用于硬伤
```

**铁律**：模型不负责写汉字（榜题/原文/印章由工具叠真字）。
**计数**：不设机械确证门槛——把"可机械确证"当硬门槛，只会逼出机械的图（[rounds/r05-review.md](subjects/jiu-wei-hu/rounds/r05-review.md)）。

> ⚠️ 初版工艺是「ControlNet 锁死可数特征 → 白描出图」，**已废弃**：实测证明决定成败的是
> **prompt 的写法**（点名式 8/8 出九尾 vs 描述式 1/6），那套控制装置是在给不存在的问题造机器。
> `scripts/control_image.py` 降级保留，不再用于九尾狐。

**骨法**：**赭石设色工笔**（R7 定案）。原定的白描墨线路线在 R8 验证过（4/4 出九尾）但视觉抓力弱，故改用设色。
鹿蜀沿用同一骨法句（逐字相同），跨件一致由此保证。

**引擎**：同机两条，按"特征离模型的概念有多远"选：

| 引擎 | 特点 | 什么时候用 |
|------|------|-----------|
| **Z-Image-Turbo**（默认） | 快（~60 s/张）、12–20 步；**负向通道是空的**（`ConditioningZeroOut`，cfg=1）；本骨法下**几乎必盖乱码印** | 常规条目（鹿蜀、九尾狐都是它出的） |
| **Qwen-Image** | 慢（~2.5 min/张）、细节密；**有真负向**；**不带"必盖印"先验** | 特征与概念冲突时（猼訑的"九尾羊"：Z-Image 21 张 0 中，Qwen-Image 一次就成立） |

> ⚠️ 两条引擎的骨法句**不能照抄**：Qwen-Image 上 STYLE 原句出的是白描墨线，
> 要**保留 STYLE 逐字不动、追加一句显式设色**（`The ink lines are washed with soft ochre and warm brown.`）；
> 而设色词会把物种拉向"褐色犬科"（猼訑 R4 六张里四张跑成狼）——补色必须多出几张、逐张验形。

### ⚠️ 印面：模型自盖的乱码印，措辞压不住（鹿蜀 R1–R3 + R5、九尾狐 R9 实测）

Z-Image-Turbo 在"册页 · 陈年纸本"这类骨法下，**几乎每张都在纸角盖红色印章或写伪字**：
鹿蜀 R1 抽查 20 张命中 19 张，连已交付的九尾狐 R7 定稿四角也有淡红印。
**两条"用 prompt 抑印"的路都已证伪**：

| 路线 | 做法 | 结果 |
|------|------|------|
| 否定式（R3） | `no seal / no stamp / no writing` 三种写法 | **9 张全无效** |
| 改写先验（R5 / R9） | 换媒介名词（册页→未装裱单片）/ 画面占满不留空边 / 换素白纸 | **24 张全无效（12/12 有印 ×2 件）** |

印的位置也稳定（右侧两角 + 下缘空白），像一条强先验而不是随机噪声。于是只剩两条路：
**多出几张挑干净的**（命中率约 1/20）与 **工具擦除**。

| 环节 | 做法 |
|------|------|
| 判据 | 每张候选的**四角 12% / 6× 放大目视**（`scripts/corner_sheet.py` 固定版面出图并自检；`scripts/seal_check.py` 只做机械筛） |
| ⛔ 反用禁止 | **机械筛只能"报疑"，不能"报安"**：被判 `CLEAN` 的 5 张（鹿蜀 3 + 九尾狐 2）目视全都有印 —— 阈值一放宽就误报、一收紧就漏报（自动定性四种判据早全败，见 r01-review §四） |
| 擦除 | `scripts/patch_region.py`：人工给坐标 → 用**同图**内一块干净纸覆盖 + 羽化，带自检（残留朱砂 ≤5%、接缝亮度差 ≤30），并**与未擦除版逐像素核对**（差异必须全部落在补丁框内），在 manifest 记 `seal_erasure` |
| 交付 | 首选成品必须**擦除后四角干净**；形态更强但有印、且不加擦除的降为 `control` / `retired-control` |

> **本期实际结果**：鹿蜀定稿 01-lu-shu.png 四角 12%/6× 复核**本来干净**（保持不动）；
> 九尾狐定稿 01-jiu-wei-hu.png 的 BL/BR 两枚淡印已擦除（差异 7024 px 全在补丁框内），
> 原样留档在 `controls/jiu-wei-hu-r7-m202-seal-tainted.png`。

> 💡 **"更浓"要付系列一致的账**：R5/R9 证明"bold 虎纹 / 更浓的尾巴"确实画得出来，
> 但它同时把墨色与对比拉高 —— 虎纹候选加权 4.38 < 定稿 4.60、狐候选 4.63 < 定稿 4.80。
> 下一件若要浓，应当把骨法句的纸色/墨色一起调暗，并**让两件同轮重跑**。

## 七、检查清单

- [ ] `comfyui_gen.py --check` 通过
- [ ] 原文已逐字核对底本，卷次标注正确
- [ ] **尾数已裁图放大目视点数并留档**（标注"目视点数，非机械确证"）
- [ ] 榜题 / 原文 / 印章由工具叠加（`typeset_zanzhi.py`），非模型生成
- [ ] 成品尺寸 1080x1440（3:4）
- [ ] 控制图条目已标注为废弃（若该条目无控制图，说明用的是纯文生图）
- [ ] `manifest.json` 记录 seed + prompt_id + prompt 原文
- [ ] 定稿已脱敏（`ffkit strip`）
- [ ] 排版自检通过（榜题 / 点睛句 / 原文区确实有墨）
- [ ] **四角 12% / 6× 放大目视无乱码印/伪字**（`corner_sheet.py` 出图；`seal_check.py` 只报疑，**不能据它的 CLEAN 放行**）
- [ ] 若用了擦除：`patch_region.py` 自检通过，且**与未擦除版逐像素核对**（差异必须全在补丁框内），manifest 记 `seal_erasure`
- [ ] 写法按已证结论写：**英文点名 + 特征逐项**（中文直述会丢虎纹、偏色，三件 15/15 失败）
- [ ] 若特征与"模型已知的概念"冲突（九尾羊、背上长眼）：先试**复合形容词**写法，不成立就**换引擎**（Z-Image → Qwen-Image）
- [ ] 用 Qwen-Image 时：STYLE 逐字保留 + 追加一句显式设色；**补色后逐张验形**（设色词会把物种拉走）
- [ ] 跨引擎对照若跑过，已记入 `rounds/rNN-review.md`（Seedream 特征最强但 6/6 题款盖章，不换代）
- [ ] 抑印轮已记入 `rounds/rNN-review.md`（R5/R9 结论：**否定式与改写先验都不能抑印**）
- [ ] 若追求"更浓"（浓虎纹 / 更浓的尾巴）：已确认骨法与两件同期一起调，否则必掉 E 系列一致
