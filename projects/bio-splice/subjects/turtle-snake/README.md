# 子主题：龟 + 蛇（玄武）

> 🌐 语言：**中文** ｜ [English](README.en.md)

> 返回[项目首页](../../README.md) ｜ 部位表见 [`parts.md`](parts.md) ｜ 开发记录见 [`rounds/`](rounds/)

> **全子主题总览图**：[`sheet.jpg`](sheet.jpg) —— 每期一行，把该期成品拼在一起（`bash make_sheet.sh subject turtle-snake` 可复现）

## 一、概念：一个**已经存在的**合体

**四象之「玄武」就是龟蛇合体**——典籍里的拼接体（《礼记》《楚辞》等有龟蛇之说）。
与 `cat-eagle`（拆一个词）、`dragon-nines`（执行古人的部件表）不同，
这个子主题的钩子是**复刻一个现成的形象**：玄武本来就是一龟一蛇缠在一起。

**底座 ＝ 龟**；供体 ＝ 蛇的**身体件**：颈 N1 / 尾 N2 / 缠体 N3（+鳞 N5 备用）。
**不给蛇头**——头部件不可移植（规律 73，已由 dragon-nines 的 D2/D3 实测）。

## 二、为什么这个子主题机制上合适

| 规律 | 对本子主题的含义 |
|------|------------------|
| 66 占位可以**腾出** | 龟有短颈、小尾 → 底座刻意不写这两处，把位置腾给 N1 / N2 |
| 67 **空位新增 > 腾出占位** | 缠体 N3（壳上本来是空的）本该最容易成——但实测它怕的是写法，见下 |
| 73 头部件不可移植 | 玄武只做**颈 / 尾 / 缠体**，不做蛇头 |
| 79 姿态句不得提到移植件 | 所有姿态句都不提「颈」「尾」「盘」 |
| 80 呈现层不是中性的 | 期 02 由 PLAN 的「低机位竖幅」**改成平视全身**，避开末端部件被个体化的坑 |

## 三、核心发现：**空间关系从句会失效**（规律 81）

N3 缠体第一轮**完全没出现**。它不是占位问题，而是写法问题：

| 写法 | 结果 |
|------|------|
| ❌ `the thick coiled body of a large snake wrapped around its shell` | 空操作 |
| ✅ `thick snake coils around its shell` | 落地（最短最稳） |

> **关系从句（`X wrapped around Y`）不被执行；名词短语（`X coils around Y`）才执行。**
> 这是规律 69 的延伸：不只是「复合部件要拆开写」，**部件与底座之间的空间关系也要写直白**。

## 五、子主题总结（收官后自评）

### 1. 蛇的身体件里，能做的都做到了

| 类型 | 部位 | 结果 |
|------|------|------|
| 腾出占位 | N1 蛇颈、N2 蛇尾 | ✅ **完整成立**（且换 seed 可复现） |
| 空位新增 | N3 缠体 | ✅ 成立，但**写法敏感**（规律 81） |
| 跨区域叠加 | N1+N2、N1+N2+N3 | ✅ 三件同体仍是一只个体 |
| 头部件 | N4 蛇头 | ⛔ 不做（规律 73） |

### 2. 这个子主题贡献的两条经验

**（1）这是「腾出占位」第一次完整成立。**
dragon-nines 的腾出占位（爪、鳞）只到「部分成立」，所以一度以为腾出不如空位；
本期 N1/N2 都完整落地，说明**腾出占位能不能成，取决于底座对该部位的依赖程度**：
龟的颈与尾是**可以从描述里删掉而不伤底座**的（删了龟还是龟），
而猫的爪、蛇的鳞**删掉就伤到底座的可信度**（所以模型会补回来）。

**（2）写法敏感度高于预期。**
同一个部件、同一个底座、同一个 seed，只改句子结构就从 0% 变成 100%（规律 81）。
→ 以后凡是「该成却没成」的部位，**先怀疑写法，再怀疑占位**。
